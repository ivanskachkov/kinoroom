# KinoRoom

Сайт для совместного просмотра фильмов и видео. Создаёте комнату, отправляете ссылку друзьям, и у всех одновременно работают пауза, перемотка и выбор фильма. Рассчитан на то, чтобы жить на Raspberry Pi.

## Что умеет

- **Комнаты по ссылке** — без регистрации, достаточно ввести имя.
- **Синхронный плеер.** Пауза, перемотка и смена видео срабатывают у всех. Если кто-то отстал, плеер сам догоняет комнату.
- **Источники видео:**
  - **YouTube** — по ссылке работает всегда, поиск включается ключом API;
  - **Internet Archive** — тысячи фильмов в общественном достоянии, поиск работает без ключа;
  - **прямые ссылки** на `.mp4`, `.webm` и потоки `.m3u8`;
  - **своя медиатека** — папка с видео на диске малинки.
- **Поиск фильмов и сериалов** через TMDB: постеры, описания, трейлеры. Нужен ключ.
- **Очередь**, **чат** и **реакции** поверх видео.
- **Телефоны**, включая iPhone. В Safari: «Поделиться» → «На экран Домой», и сайт открывается как приложение.
- **Пароль на весь сайт** (по желанию).

## Быстрый старт на компьютере

Нужен Node.js версии 20 или новее.

```bash
npm install
npm start
```

Откройте http://localhost:3000. Ключи API и остальные настройки — в файле `.env`, образец лежит в `.env.example`.

## Запуск на Raspberry Pi

Подойдёт Pi 3, 4, 5 или Zero 2 W с Raspberry Pi OS. Нагрузка на малинку маленькая: видео с YouTube и Archive идёт зрителям напрямую, а через малинку проходят только команды синхронизации и чат. Исключение — медиатека: её файлы раздаёт сама малинка (об этом ниже).

**1. Установите Node.js 22:**

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
```

**2. Скопируйте проект на малинку** (папку `node_modules` копировать не нужно):

```bash
scp -r kinoroom pi@raspberrypi.local:~/
```

**3. Установите зависимости и настройте:**

```bash
cd ~/kinoroom
npm ci --omit=dev
cp .env.example .env
nano .env
```

**4. Включите автозапуск.** В `deploy/kinoroom.service` замените `pi` на своё имя пользователя, если оно другое, а затем:

```bash
sudo cp deploy/kinoroom.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now kinoroom
```

Логи смотрятся командой `journalctl -u kinoroom -f`, перезапуск после обновления — `sudo systemctl restart kinoroom`.

**5.** В домашней сети сайт открывается по адресу `http://raspberrypi.local:3000`.

## Как открыть сайт друзьям через интернет

**Обязательно задайте `SITE_PASSWORD` в `.env`**, прежде чем открывать сайт наружу.

**Cloudflare Tunnel (рекомендую).** Бесплатно, даёт HTTPS, открывать порты на роутере не нужно, WebSocket поддерживается.

```bash
curl -L -o cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-arm64.deb
sudo dpkg -i cloudflared.deb
cloudflared tunnel --url http://localhost:3000
```

Последняя команда выдаст адрес вида `https://что-то.trycloudflare.com`. Он меняется при каждом запуске, поэтому годится для проверки. Для постоянного адреса нужен свой домен в Cloudflare: [инструкция по именованному туннелю](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/get-started/create-local-tunnel/).

**Tailscale.** Подходит, если смотрите только своей компанией. Каждый ставит Tailscale, и сайт доступен по внутреннему адресу малинки, а в открытый интернет не попадает вообще.

> Если сайт открыт по HTTPS, браузер не станет проигрывать видео по ссылкам `http://`. Используйте ссылки с `https://`.

## Ключи API

Оба ключа необязательны: без них работают ссылки, Internet Archive и медиатека.

**TMDB** (поиск фильмов и сериалов). Зарегистрируйтесь на [themoviedb.org](https://www.themoviedb.org), затем «Настройки» → «API» → создайте ключ типа Developer. Для личного использования он бесплатный. В `.env` подойдёт и «API Key», и «API Read Access Token».

**YouTube Data API v3** (поиск по YouTube):

1. В [Google Cloud Console](https://console.cloud.google.com) создайте проект.
2. «APIs & Services» → «Library» → **YouTube Data API v3** → «Enable».
3. «Credentials» → «Create credentials» → «API key». Ключ лучше ограничить, разрешив ему только YouTube Data API.

Бесплатная квота — примерно 100 поисков в сутки. Результаты кэшируются на 6 часов, а в карточке фильма поиск по YouTube запускается только кнопкой, чтобы не тратить квоту.

## Медиатека

Укажите в `.env` папку с видео: `MEDIA_DIR=/mnt/hdd/movies`. Файлы из неё находятся через ту же строку поиска.

- Браузеры надёжно играют **MP4 (H.264 + AAC)** и **WebM**. Файлы MKV и AVI часто не воспроизводятся. MKV с видео в H.264 можно быстро переупаковать без перекодирования:
  ```bash
  ffmpeg -i film.mkv -c:v copy -c:a aac -movflags +faststart film.mp4
  ```
  Полное перекодирование на малинке идёт очень медленно, его лучше делать на компьютере.
- Видео из медиатеки каждый зритель скачивает с малинки. Для друзей из других сетей упираетесь в **исходящую скорость вашего интернета**: фильму в 1080p нужно около 5–8 Мбит/с на каждого зрителя.

## Как работает синхронизация

Сервер хранит состояние комнаты как «позицию в момент времени»: `{ playing, position, updatedAt }`. Каждый браузер сверяет свои часы с сервером (как NTP, по минимальной задержке) и сам вычисляет, где сейчас должно быть видео. Раз в секунду плеер проверяет расхождение:

- меньше 0,25 с — всё в порядке;
- до 2 с (только файлы) — скорость незаметно меняется на ±5%, пока видео не догонит;
- больше 1,2 с (YouTube) или 2 с (файлы) — перемотка, но не чаще раза в 4 с, чтобы медленный интернет не уходил в цикл «перемотка → буферизация».

Управлять плеером можно только через кнопки сайта, поэтому каждое действие однозначно уходит на сервер и рассылается всем участникам.

## Ограничения

- Комнаты хранятся в памяти: после перезапуска сервера они пустые, но ссылки на них продолжают работать.
- Видео YouTube, которые владелец запретил встраивать на другие сайты, и платные фильмы YouTube не играют.
- Синхронизировать страницы других сайтов с их собственным плеером невозможно, работают только прямые ссылки на файлы и потоки.
- На iPhone ползунок громкости не работает (так устроен iOS), звук регулируется кнопками телефона.

## Структура

```
server.js            — HTTP-сервер, статика, подключение модулей
lib/rooms.js         — комнаты, синхронизация, очередь, чат (Socket.IO)
lib/search.js        — прокси к TMDB, YouTube и Internet Archive (ключи не попадают в браузер)
lib/library.js       — поиск по MEDIA_DIR
lib/auth.js          — общий пароль на сайт
public/js/room.js    — логика комнаты и досинхронизация плеера
public/js/players.js — плееры YouTube и <video>/HLS с общим интерфейсом
public/js/search.js  — строка поиска и карточки результатов
deploy/              — systemd-сервис для малинки
```
