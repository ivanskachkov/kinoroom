# KinoRoom

Сайт для совместного просмотра фильмов и видео. Создаёте комнату, отправляете ссылку друзьям, и у всех одновременно работают пауза, перемотка и выбор фильма. Рассчитан на то, чтобы жить на Raspberry Pi.

## Что умеет

- **Комнаты по ссылке** — без регистрации, достаточно ввести имя.
- **Комната помнит, где остановились.** Видео, позиция, очередь и чат хранятся 30 дней с последней активности и переживают перезапуск сервера. Вернулись завтра — фильм стоит на паузе на том же месте.
- **Общий список комнат** на главной, с поиском по названию и фильму. Комнату можно закрыть паролем. Друзья, пришедшие по ссылке-приглашению, входят без пароля.
- **Синхронный плеер.** Пауза, перемотка и смена видео срабатывают у всех. Если кто-то отстал, плеер сам догоняет комнату.
- **Источники видео:**
  - **YouTube** — по ссылке работает всегда, поиск включается ключом API;
  - **Internet Archive** — тысячи фильмов в общественном достоянии, поиск работает без ключа;
  - **прямые ссылки** на `.mp4`, `.webm` и потоки `.m3u8`;
  - **своя медиатека** — папка с видео на диске малинки.
- **Поиск фильмов и сериалов** через TMDB: постеры, описания, трейлеры. Нужен ключ.
- **Голосовой чат.** Любой участник может включить микрофон, и его слышат все в комнате. Слушателям микрофон не нужен. Пока кто-то говорит, фильм приглушается (это можно отключить).
- **Очередь**, **чат** и **реакции** поверх видео. В полноэкранном режиме новые сообщения всплывают поверх фильма, а ответить можно, не выходя из него. На компьютере у новых сообщений есть звук, он выключается колокольчиком в чате.
- **Телефоны**, включая iPhone. В Safari: «Поделиться» → «На экран Домой», и сайт открывается как приложение.
- **Пароль на весь сайт** (по желанию).

## Быстрый старт на компьютере

Нужен Node.js версии 20 или новее.

```bash
npm install
npm start
```

Откройте http://localhost:3000. Ключи API и остальные настройки — в файле `.env`, образец лежит в `.env.example`.

## Запуск на Raspberry Pi

Нагрузка на малинку маленькая. Видео с YouTube и Archive идёт зрителям напрямую, голос — напрямую между браузерами. Через малинку проходят только команды синхронизации, чат и служебные сообщения голосового чата. Исключение — медиатека: её файлы раздаёт сама малинка (об этом ниже).

**Сколько нужно памяти.** Замер сервера под нагрузкой (боты с чатом, перемотками и голосовыми сигналами, по 20 секунд):

| Сценарий | Память сервера | Процессор (оценка для Pi 4) |
|---|---|---|
| Простой | ~63 МБ | 0% |
| 15 человек, 3 комнаты | ~68 МБ | ~3% одного ядра |
| 100 человек, 10 комнат | ~72 МБ | ~8% |
| 300 человек, 20 комнат | ~105 МБ | ~30% |

Вместе с Raspberry Pi OS Lite (~150 МБ) и cloudflared (~40 МБ) получается 250–300 МБ. **Хватит любой малинки с 1 ГБ ОЗУ и больше** (Pi 3B+, 4, 5). Pi Zero 2 W с 512 МБ тоже справится, если ставить систему без рабочего стола. Замерено на Windows; на малинке Node.js потребляет примерно столько же.

**1. Установите Node.js 22:**

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
```

**2. Скопируйте проект на малинку** (папку `node_modules` копировать не нужно):

```bash
scp -r kinoroom pi@raspberrypi.local:~/
```

**3. Установите зависимости и настройте:**

```bash
cd ~/kinoroom
npm ci --omit=dev
cp .env.example .env
nano .env
```

**4. Включите автозапуск.** В `deploy/kinoroom.service` замените `pi` на своё имя пользователя, если оно другое, а затем:

```bash
sudo cp deploy/kinoroom.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now kinoroom
```

Логи смотрятся командой `journalctl -u kinoroom -f`, перезапуск после обновления — `sudo systemctl restart kinoroom`.

**5.** В домашней сети сайт открывается по адресу `http://raspberrypi.local:3000`.

## Как открыть сайт друзьям через интернет

**Обязательно задайте `SITE_PASSWORD` в `.env`**, прежде чем открывать сайт наружу.

**Cloudflare Tunnel (рекомендую).** Бесплатно, даёт HTTPS, открывать порты на роутере не нужно, WebSocket поддерживается.

```bash
curl -L -o cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-arm64.deb
sudo dpkg -i cloudflared.deb
cloudflared tunnel --url http://localhost:3000
```

Последняя команда выдаст адрес вида `https://что-то.trycloudflare.com`. Он меняется при каждом запуске, поэтому годится для проверки. Для постоянного адреса нужен свой домен в Cloudflare: [инструкция по именованному туннелю](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/get-started/create-local-tunnel/).

**Tailscale.** Подходит, если смотрите только своей компанией. Каждый ставит Tailscale, и сайт доступен по внутреннему адресу малинки, а в открытый интернет не попадает вообще.

> Если сайт открыт по HTTPS, браузер не станет проигрывать видео по ссылкам `http://`. Используйте ссылки с `https://`.

## Ключи API

Оба ключа необязательны: без них работают ссылки, Internet Archive и медиатека.

**TMDB** (поиск фильмов и сериалов). Зарегистрируйтесь на [themoviedb.org](https://www.themoviedb.org), затем «Настройки» → «API» → создайте ключ типа Developer. Для личного использования он бесплатный. В `.env` подойдёт и «API Key», и «API Read Access Token».

**YouTube Data API v3** (поиск по YouTube):

1. В [Google Cloud Console](https://console.cloud.google.com) создайте проект.
2. «APIs & Services» → «Library» → **YouTube Data API v3** → «Enable».
3. «Credentials» → «Create credentials» → «API key». Ключ лучше ограничить, разрешив ему только YouTube Data API.

Бесплатная квота — примерно 100 поисков в сутки. Результаты кэшируются на 6 часов, а в карточке фильма поиск по YouTube запускается только кнопкой, чтобы не тратить квоту.

**TURN для голосового чата** (нужен, только если у кого-то голос не подключается):

- **Cloudflare**: в [панели Cloudflare](https://dash.cloudflare.com) откройте «Realtime» → «TURN Server» → «Create». Скопируйте «Turn Token ID» в `CF_TURN_KEY_ID`, а API token — в `CF_TURN_API_TOKEN`. Стоит $0,05 за ГБ трафика через ретранслятор; час разговора одного человека — примерно 20 МБ на каждого слушателя, и ретранслятор используется только там, где напрямую не получилось.
- **Свой coturn или любой другой TURN**: заполните `TURN_URLS`, `TURN_USERNAME` и `TURN_CREDENTIAL`.

## Сторож: автоматический перезапуск

`deploy/watchdog.sh` раз в 30 минут проверяет малинку:

- **Упавшие службы** перезапускает, в том числе те, которые systemd перестал поднимать после серии сбоев подряд. Если нет интернета, службы не трогает.
- **Зависший KinoRoom** (процесс жив, но сайт не отвечает на запросы) тоже перезапускает. Перед этим проверяет дважды, чтобы не реагировать на один медленный ответ.
- **Tailscale Funnel** включает заново, если настройка сбросилась.
- **Уведомление** о каждом перезапуске присылает владельцу в Telegram через любого бота, у которого в `.env` есть `TELEGRAM_BOT_TOKEN` и `TELEGRAM_OWNER_ID`.

Установка:

```bash
sudo install -m 755 deploy/watchdog.sh /usr/local/sbin/pi-watchdog
sudo cp deploy/pi-watchdog.service deploy/pi-watchdog.timer /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now pi-watchdog.timer
```

Что проверять, задаётся в `/etc/default/pi-watchdog`:

```bash
WATCHDOG_SERVICES="kinoroom restaurant-bot tgbot tailscaled"
WATCHDOG_HTTP_CHECKS="kinoroom=http://localhost:3000/login"
WATCHDOG_FUNNEL_PORT=3000
WATCHDOG_NOTIFY_ENV=/home/is/restaraunt-create-bot/.env
```

Журнал проверок смотрится командой `journalctl -u pi-watchdog`, запуск вне очереди — `sudo systemctl start pi-watchdog`. После правок в `watchdog.sh` повторите первую команду установки.

## Комнаты: пароли, приглашения, список

- **Создатель комнаты** — её владелец. Название, пароль и видимость в общем списке задаются сразу при создании («Название и пароль комнаты» на главной) или потом, шестерёнкой в шапке комнаты. Владельца браузер узнаёт по ключу, сохранённому при создании. С другого устройства вы зайдёте как обычный участник.
- **Пароль на комнату** спрашивается у тех, кто пришёл из общего списка или по коду.
- **Ссылка-приглашение** копируется кнопкой с кодом комнаты, по ней пароль не нужен. Кто однажды вошёл, дальше входит без пароля. Если ссылка ушла не туда, владелец в настройках делает новую, и старые перестают работать.
- **Комнаты, созданные до появления владельцев,** достаются первому, кто в них зайдёт.

## Горячие клавиши

Как на YouTube. Клавиши работают при любой раскладке, удержание клавиши не повторяет действие.

| Клавиша | Действие |
|---|---|
| Пробел или K | пауза / смотреть |
| ← или J | назад на 10 секунд |
| → или L | вперёд на 10 секунд |
| F | полный экран |
| M | звук |
| C | чат (в полноэкранном режиме — поле ответа поверх видео) |
| / | поиск |

## Голосовой чат

Во вкладке «Люди» или кнопкой с микрофоном под плеером любой участник включает микрофон, и его слышат все в комнате. Говорить могут несколько человек одновременно. У говорящего аватарка подсвечивается зелёным.

- **Нужен HTTPS.** Браузеры дают доступ к микрофону только по HTTPS или на `localhost`. Через Cloudflare Tunnel всё работает. По адресу `http://raspberrypi.local:3000` голоса можно слушать, но включить свой микрофон не получится.
- **Лучше в наушниках**, иначе микрофон подхватит звук фильма, и друзья услышат его дважды.
- **Если слышно не голос**, нажмите «Проверить, как меня слышно» во вкладке «Люди». Сайт запишет 4 секунды ровно того, что уходит слушателям, и проиграет. Частые причины:
  - звук фильма из колонок попадает в микрофон — нужны наушники;
  - проверка на одном компьютере в двух вкладках: вкладка-слушатель выводит ваш голос в колонки, и получается эхо;
  - голос обрывается — метка отсечки шума стоит слишком далеко вправо.
- **Как устроено.** Звук идёт напрямую между браузерами (WebRTC) и малинку не нагружает. Говорящий отправляет звук каждому слушателю отдельно: около 40 кбит/с на человека, так что для компании до ~10 человек этого хватает с запасом.
- **TURN-ретранслятор** (необязательно). Иногда прямое соединение не устанавливается: строгий NAT, некоторые мобильные операторы, корпоративные сети. Тогда нужен ретранслятор, см. раздел «Ключи API» ниже.

## Google Диск

Фильмы можно хранить на Google Диске. Видео каждому зрителю идёт прямо с серверов Google: быстро, без нагрузки на малинку и без ограничения скорости Funnel. Синхронизация такая же, как у обычных файлов.

- **Один файл:** вставьте ссылку на него в строку поиска. У файла должен быть доступ «Все, у кого есть ссылка».
- **Папка с фильмами:** укажите её ID в `GDRIVE_FOLDER_ID`. Всё из неё, включая подпапки на два уровня (например, сезоны сериала), появится в поиске в разделе «Google Диск». Кнопка «Найти, что посмотреть» в пустой комнате откроет весь список.
- **Формат:** MP4 (H.264 + AAC) или WebM. MKV и HEVC браузеры часто не играют — такой файл лучше переупаковать или перекодировать (см. «Медиатека»).

Ключ `GDRIVE_API_KEY` создаётся в том же проекте Google Cloud, что и ключ YouTube:
1. «APIs & Services» → «Library» → **Google Drive API** → «Enable».
2. «Credentials» → «Create credentials» → «API key».
3. «API restrictions» → только Google Drive API.
4. «Application restrictions» → «Websites» → адреса сайта, например `https://kinoroom.tail39befd.ts.net/*` и `http://192.168.0.127:3000/*`.

Ключ попадает в ссылку на видео и виден браузерам зрителей, поэтому ограничение по сайту обязательно. Если файл по ссылке посмотрело слишком много людей, Google может временно ограничить его скачивание.

## Медиатека

Укажите в `.env` папку с видео: `MEDIA_DIR=/mnt/hdd/movies`. Файлы из неё находятся через ту же строку поиска.

- Браузеры надёжно играют **MP4 (H.264 + AAC)** и **WebM**. Файлы MKV и AVI часто не воспроизводятся. MKV с видео в H.264 можно быстро переупаковать без перекодирования:
  ```bash
  ffmpeg -i film.mkv -c:v copy -c:a aac -movflags +faststart film.mp4
  ```
  Полное перекодирование на малинке идёт очень медленно, его лучше делать на компьютере.
- Видео из медиатеки каждый зритель скачивает с малинки. Для друзей из других сетей упираетесь в **исходящую скорость вашего интернета**: фильму в 1080p нужно около 5–8 Мбит/с на каждого зрителя.

## Как работает синхронизация

Сервер хранит состояние комнаты как «позицию в момент времени»: `{ playing, position, updatedAt }`. Каждый браузер сверяет свои часы с сервером (как NTP, по минимальной задержке) и сам вычисляет, где сейчас должно быть видео. Раз в секунду плеер проверяет расхождение:

- меньше 0,25 с — всё в порядке;
- до 2 с (только файлы) — скорость незаметно меняется на ±5%, пока видео не догонит;
- больше 1,2 с (YouTube) или 2 с (файлы) — перемотка, но не чаще раза в 4 с, чтобы медленный интернет не уходил в цикл «перемотка → буферизация».

Управлять плеером можно только через кнопки сайта, поэтому каждое действие однозначно уходит на сервер и рассылается всем участникам.

## Ограничения

- Комнаты сохраняются в папку `data/rooms`, по файлу на комнату. Срок хранения задаётся в `ROOM_TTL_DAYS`. При внезапном отключении питания во время просмотра теряется не больше 30 секунд. При обычной остановке и перезапуске сторожем не теряется ничего.
- Видео YouTube, которые владелец запретил встраивать на другие сайты, и платные фильмы YouTube не играют.
- Синхронизировать страницы других сайтов с их собственным плеером невозможно, работают только прямые ссылки на файлы и потоки.
- На iPhone ползунок громкости не работает (так устроен iOS), звук регулируется кнопками телефона.

## Структура

```
server.js            — HTTP-сервер, статика, подключение модулей
lib/rooms.js         — комнаты, синхронизация, очередь, чат, сигналы голосового чата (Socket.IO)
lib/ice.js           — STUN/TURN-серверы для голоса
public/js/voice.js   — голосовой чат (WebRTC, по соединению на пару «говорящий → слушатель»)
lib/search.js        — прокси к TMDB, YouTube и Internet Archive (ключи не попадают в браузер)
lib/library.js       — поиск по MEDIA_DIR
lib/auth.js          — общий пароль на сайт
public/js/room.js    — логика комнаты и досинхронизация плеера
public/js/players.js — плееры YouTube и <video>/HLS с общим интерфейсом
public/js/search.js  — строка поиска и карточки результатов
deploy/              — systemd-службы для малинки и сторож (watchdog.sh)
```
